# 网站分析与重构说明

## 仓库与上线关系

实际上线仓库：`LMingyao/testWebRA1`。GitHub Pages 配置为 `main` 分支的根目录，域名为 `mingyaophoto.com`。`PortfolioShowCaseWebsite` 是较早的展示实现，没有单独启用 Pages；`testWebRA1-main` 是空仓库。本次修改集中在当前线上仓库。

## 原实现的问题

- 六个 HTML 页面重复导航、页脚、字体和社交链接。新增作品需复制 HTML 结构，页面之间容易不一致。
- 首页重复加载多个版本的 jQuery 和 Slick；引用 HTTP jQuery UI，HTTPS 页面可能阻止加载。
- `head` 出现在正文内，存在多余 `/>` 和不完整标签。照片普遍没有描述文本。
- 首页与人像页重复引用部分照片。停用的法语与黑白页面仍引用已不存在的照片或页面。
- 联系页面保留 `info@example.com` 的表单动作，与真实联系邮箱不一致。
- 37 张实际展示的独立照片原始大小合计约 76.52 MiB，全部原图用于画廊，缺少响应式图片与有效的延迟加载。
- 没有内容管理入口；改文字、调整顺序、隐藏作品、上传照片都依赖直接修改源码。

## 设计保留与调整

以当前 live 网站浏览结果为依据，延续原版 Logo 的 MINGYAO / Photography 排列、手写感年份和粉色渐变，用 HTML/CSS 文字重构，替代带固定 2025 字样的图片。年份按多伦多时区自动显示，无需每年维护。原版图片仍保留在仓库。

保留 Lucida Sans 导航风格、PORTFOLIO / PORTRAIT / ABOUT ME / CONTACT 名称与白底黑字。正文延续系统无衬线字体，优化标题层级、字号、行距、字距、回退字体与移动端可读性；不依赖外部字体服务。

首页继续先展示大幅摄影作品，并保持原图比例；下方增加简短介绍、分类筛选和响应式瀑布流。全屏查看支持方向键、Escape、触屏滑动；菜单、按钮和图片补充了可访问名称。保留头像、真实邮箱、社交链接、器材信息与原始照片。

迁移 37 张独立作品，按实际画面整理为航空、风景、人像、野生动物和赛车分类。照片标题与描述是第一版编辑文字，可在后台修改。

生成的 37 张 640 像素浏览图片合计约 1.04 MiB，三档 WebP 文件总计约 11.13 MiB。该数值是文件大小对比，实际加载量随屏幕和浏览行为变化，未宣称测量加载速度。

## 可维护架构

保留静态托管。前台和后台使用共同的数据定义与验证，内容脱离页面代码。零运行依赖，不需要长期维护前端框架、数据库或打包服务。

本机管理通过仅监听 `127.0.0.1` 的 Node API 持久保存，检查 Host、Origin、会话令牌和内容版本。线上管理通过只具有仓库 Contents 权限的 GitHub 令牌保存，一次提交包括上传图片与内容，分支更新禁止强制覆盖。线上令牌只在当前页面内存中。

当前版本没有自建的账户/OAuth 服务。若以后需要多位非技术编辑直接登录、私密图库、客户选片或大规模媒体资产库，可在这些需求明确后增加 GitHub App/OAuth 与对象存储；现有数据结构和存储适配器可沿用。

## 验证

- Node 自动测试覆盖内容格式、恶意路径/链接、真实本机持久保存、过期版本冲突、跨域/未授权拒绝、源文件访问限制，以及 GitHub 非强制分支更新。
- Edge 浏览器检查桌面与 390px 手机布局、分类、全屏前后翻图与 Escape、人像/个人介绍/联系页面。
- 浏览器实际操作后台，验证编辑后保存、刷新持久存在、添加分类、编辑网站介绍、上传图片默认隐藏、生成图片文件并保存。
- 37 张原图和原版 Logo 均保留；测试数据还原后图库仍为 37 张。

本次修改位于独立重构分支；正式上线仍通过审阅并合并到 `main` 完成。
