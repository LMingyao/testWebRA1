# 网站分析与重构说明

## 仓库与上线关系

实际上线仓库：`LMingyao/testWebRA1`。GitHub Pages 配置为 `main` 分支的根目录，域名为 `mingyaophoto.com`。`PortfolioShowCaseWebsite` 是较早的展示实现，没有单独启用 Pages；`testWebRA1-main` 是空仓库。本次修改集中在当前线上仓库。

## 原实现的问题

- 六个 HTML 页面重复导航、页脚、字体和社交链接。新增作品需复制 HTML 结构，页面之间容易不一致。
- 首页重复加载多个版本的 jQuery 和 Slick；引用 HTTP jQuery UI，HTTPS 页面可能阻止加载。
- `head` 出现在正文内，存在多余 `/>` 和不完整标签。照片普遍没有描述文本。
- 首页与人像页重复引用部分照片。停用的法语与黑白页面仍引用已不存在的照片或页面。
- 联系页面保留 `info@example.com` 的表单动作，与真实联系邮箱不一致。
- 37 张实际展示的独立照片原始大小合计约 76.52 MiB，全部原图用于画廊，缺少响应式图片与有效的延迟加载。
- 没有内容管理入口；改文字、调整顺序、隐藏作品、上传照片都依赖直接修改源码。

## 设计保留与调整

以当前 live 网站浏览结果为依据，延续原版 Logo 的 MINGYAO / Photography 排列和粉色渐变，用 HTML/CSS 文字重构，替代带固定 2025 字样的图片。按用户反馈去掉品牌中的年份，避免视觉过期及每年维护。原版图片仍保留在仓库；页脚版权年份单独自动更新。

保留 Lucida Sans 导航风格与白底黑字。全站入口重新组织为 WORK / ABOUT / CONTACT：作品分类归入 WORK 菜单，统一控制整页内容，避免轮播与分类图库各自运行。人像沿用 ptr.html 地址，同时归入作品导航。正文延续系统无衬线字体，不依赖外部字体服务。

原站 6 张细长横幅作为同一个作品序列的开篇，不重复出现在下面。取消自动播放，以明确的左右按钮、键盘及触屏滑动交给访客控制；分类切换同时筛选横幅和后续作品。所有照片进入同一个分类预览序列，消除独立轮播与独立分类图库造成的交互割裂。后台明确配置展示位置，避免靠图片尺寸猜测用途。

取消原设计中的介绍口号、作品总数、逐张标题与分类文字、灰色固定画框和第二套筛选栏。默认 Multi view，算法按图片长宽比与容器宽度选择分行，每行最多三张并提高最小观看宽度，避免竖图被挤成缩略图。在保留顺序和完整画面的前提下，使每行等高、间距一致；极端比例独立成行，比例合适的末行铺满，过高末行限制高度并居中，手机为单列。响应式图片的 sizes 根据实际卡片宽度生成。页头可切换 Single view，保留分类和当前照片；全屏选择同步单张视图。横幅箭头移至图片下方，避免遮挡画面。白底全屏预览只保留关闭与前后切换；图片描述保留给屏幕阅读器。保留头像、真实邮箱、社交链接、器材信息与原始照片。

导航和视图切换使用 12px 字号与更清楚的灰度，分类入口改为下箭头。关于页简介缩短、照片与文字顶部对齐，器材列表可展开；联系页取消大口号并突出邮箱。短页面的页脚靠近视口底部，避免页脚下方出现大段空白。照片顺序、首页精选标记和原始照片保持用户当前配置。

主页作为 Selected work 精选入口，独立的 homeSelected 标记决定是否入选；分类页仍展示该分类全部已展示照片。该标记与 published、轮播首图 featured 分开，不会自动公开隐藏作品。初始配置沿用 B 布局稿七张既有照片及原有横幅，后台提供勾选和筛选。查看旧版 BW.html 的黑白 Logo 后，保留当前文字品牌与粉色渐变，并将渐变收细；最终不添加实心方块。渐变用于 Logo、联系邮箱下划线和页脚横贯内容宽度的细线；导航采用短粉色标记，视图选中状态采用深色文字与细线，照片周围保持白底。

设计参考：[Nadav Kander 的系列作品](https://www.nadavkander.com/works-in-series)与 [Chris Burkard 的作品入口](https://www.chrisburkard.com/Pages/Portfolio)。借鉴作品优先、清楚的导航层级和留白方式，具体布局结合本站横幅、航空、人像和风景内容重新组织。

迁移 37 张独立作品，按实际画面整理为航空、风景、人像、野生动物和赛车分类。照片标题与描述是第一版编辑文字，可在后台修改。

生成的 37 张 640 像素浏览图片合计约 1.04 MiB，三档 WebP 文件总计约 11.13 MiB。该数值是文件大小对比，实际加载量随屏幕和浏览行为变化，未宣称测量加载速度。

## 可维护架构

保留 GitHub Pages 静态托管，前端使用原生模块，没有框架运行依赖。前台和后台使用共同的数据定义与验证，内容脱离页面代码；当前线上内容由 Cloudflare Workers 与 D1 管理，照片继续保存在 GitHub。

本机管理通过仅监听 `127.0.0.1` 的 Node API 持久保存，检查 Host、Origin、会话令牌和内容版本。当前云后台通过管理员密码登录，使用受保护的会话；照片上传令牌只保存在 Worker secret。D1 保存检查内容版本并保留修改历史。静态模式仍保留 GitHub 保存适配器，其令牌仅在页面内存中，一次提交包括图片与内容，禁止强制覆盖分支。

当前版本采用单管理员密码与八小时会话，登录和保存接口有来源检查与限速。多管理员、私密图库、客户选片或大规模媒体库可以在需求明确后扩展。照片隐藏只控制前台展示，公开仓库中的文件与历史仍可访问。云端部署与验证情况见 `docs/d1-plan.md`。

## 代码整理

删除已经完成任务的一次性迁移与标题整理脚本、后台的旧配色覆盖文件、未使用的样式与介绍字段，以及已停用的法语与黑白入口页及其生成逻辑。主页作品筛选只保留实际使用的统一序列逻辑。原始照片、历史 Logo 和在用页面地址保留。

图库控制器、响应式图片生成和大图查看分别维护，状态封装在页面实例中；关于与联系页面不加载图库模块。图片生成采用明确的参数对象，避免多个布尔参数混淆，并处理小尺寸图片与缺少缩略图时的重复 srcset 宽度。构建和两种保存方式共用图片路径集合，后台使用同一集合筛选待保存文件。

后台排序按钮改为每次渲染先计算区域首尾，避免为每张卡片重复遍历全部照片；搜索关键字和区域筛选规则也集中处理。Logo 的基线与粉色条对齐逻辑保持原样。

## 验证

- 当前 34 项 Node 测试覆盖内容格式、路径与访问边界、本机与 D1 保存、版本冲突、密码会话与限速、上传重试、非强制 GitHub 更新、统一分类序列、自动排版、分组与独立展示、响应式图片及旧数据兼容。
- 浏览器检查桌面与 390px 手机布局、统一分类菜单、整页筛选、横幅手动切换和同一预览序列、无标题/数量的展示、方向键与 Escape、浏览历史、手机菜单及人像页面。
- 浏览器实际操作后台，验证编辑后保存、刷新持久存在、添加分类、编辑网站介绍、展示位置切换同步前台、轮播首图、区域内排序、上传图片默认隐藏、生成图片文件并保存。
- 实际保存取消首页精选，确认主页移除而所属分类仍保留，随后恢复初始配置；检查视图切换、同一行高度、手机宽度、导航与箭头不覆盖图片。
- 在独立临时 GitHub 分支完成真实 API 验证：图片与 JSON 一次提交、重新读取内容、拒绝过期版本保存；验证后移除临时分支，未修改 main。
- 前台与后台的 Logo 均为文字和 CSS，品牌中不再显示年份。
- 37 张原图和原版 Logo 均保留；测试数据还原后图库仍为 37 张。

第一轮重构已合并到 `main` 并上线。后续审美一致性调整使用固定导航、共同页面网格、统一箭头和品牌变量；完整规则见 `docs/design-rules.md`。代码发布沿用审阅并合并到 `main` 的流程。

按用户要求撤回本轮新增的三张 Lightroom 照片、后台记录和九个浏览文件。当前仅保留原有 37 张作品；后续选片由用户自行完成。
