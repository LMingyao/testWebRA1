# Supabase 接入与费用方案

核对日期：2026-10-01。方案适用于单个摄影师管理当前摄影作品站。

## 决定与当前状态

采用 GitHub Pages 托管页面，Supabase PostgreSQL 管理内容，Supabase Storage 托管照片，Supabase Auth 管理后台邮箱与密码。按用户选择，先采用 Free；暂不购买 Pro 或任何附加服务。正式站点需接受免费额度与闲置暂停限制，将来确有容量或持续运行需求再评估升级。尚未创建云项目或开通付费服务；本机后台和现有站点运行方式不变。

本阶段提供数据库建表/权限脚本与可重复生成的迁移材料。云数据库、密码登录页面和照片上传适配器尚未接通，不能把当前后台当作已经具有 Supabase 登录的版本。项目建立后实施并验证应用接入，再切换公开站点。

## 当前容量与费用

现有 37 张作品：原图 76.52 MiB，640/1280/1920 三档 WebP 合计 11.12 MiB，头像 1.51 MiB；共 149 个被内容引用的独立文件，合计 89.16 MiB。内容 JSON 约 19.6 KiB；这不是 PostgreSQL 实例实际磁盘占用，数据库本身还有系统表和索引。

| 套餐 | 基础月费，美元，未含税 | 文件存储 | 数据库 | 非缓存 / 缓存出站流量 |
| --- | --- | --- | --- | --- |
| Free | 0 | 1 GB | 500 MB | 各 5 GB/月 |
| Pro，单个 Micro 项目 | 25 | 100 GB | 8 GB 磁盘 | 各 250 GB/月 |

Pro 包含每月 10 美元计算资源抵扣，可覆盖一个 Micro 实例；增加云项目、更大的实例或可选附加服务会增加费用。25 美元/月对应基础年费 300 美元。现有域名续费和税费另计；本方案不需要 Supabase 自定义 API 域名附加项。

Free 可能在一周闲置后暂停，且无自动数据库备份；Pro 不因闲置暂停，含保留七天的每日数据库备份。照片对象不在数据库备份内，需要保留独立文件备份。

访问流量示例：若每次浏览下载 3 MB 的图片与数据，1,000 次约 3 GB，10,000 次约 30 GB。此为预算量级估算，不是访客额度承诺。实际量取决于浏览深度、图片尺寸、浏览器缓存及 CDN 命中；缓存与非缓存流量按不同额度分别计算。原图下载另计。

正式配置保留 Spend Cap，但它不覆盖计算资源升级、额外项目和所有附加服务，不能理解成任何情况下总账单都锁死为 25 美元。图片使用已有三档 WebP，不启用按量动态图片转换。只建一个正式项目，开发继续使用本机环境。

密码找回邮件需配置生产 SMTP；可先选择支持 SMTP 的免费邮件套餐，供应商选定时再核对额度。本轮不创建邮件账户或修改 DNS。

## 数据与权限

- `gallery_settings`：公开网站文案、邮箱、社交链接、头像路径与内容版本。不存密码、GitHub 令牌或服务密钥。
- `gallery_categories`：稳定分类 ID、名称与顺序。
- `gallery_photos`：宽高、描述、分类、顺序、顶部轮播/画廊位置、首页精选与展示状态，以及浏览图片路径。
- `gallery_originals`：原图路径与照片 ID，仅管理员可读取。
- `gallery_admins`：允许编辑的 Auth 用户 ID，只有项目管理端能够设置。

管理员预先创建，关闭公开注册。登录并不自动获得管理权限，必须列入管理员名单。数据库和 Storage 通过 RLS 拒绝访客或普通登录账户的写入。

为了避免草稿上传后可凭网址访问，`gallery-images` 和 `gallery-originals` 都使用私有存储桶。访客只能为已发布照片的浏览版本及公开头像取得短期签名链接；原图只有管理员能够访问。签名链接到期前仍有效，因此撤下作品不能撤销访客已获得的文件或尚未过期的链接。前台接入时需设置较短有效期，并在必要时刷新链接。

迁移保留现有选片、分类、尺寸和顺序，不从 Lightroom 增补照片。原图复制到私有原图桶，前台图片路径指向最大 WebP 版本。当前公开 Git 仓库及其历史中的原图不会因为迁移自动变成私密资料；未来新照片不再提交到公开 Git。

## 准备与接入顺序

1. 运行 `npm run prepare:supabase`，在 `.local/supabase/` 生成媒体清单与 SQL 种子。生成器只读取现有内容与文件，不连接云、不上传文件。
2. 创建 Supabase 项目，执行 `supabase/schema.sql`。上传清单中的文件到对应私有桶，再执行生成的 `seed.sql`。种子只适用于空内容表，不覆盖已有图库。
3. 在 Supabase Auth 管理端创建管理员，在 `gallery_admins` 登记其用户 ID，关闭公开注册，配置生产站点/本机回调地址及 SMTP。
4. 实现前台公开内容读取、签名图片地址与后台密码登录/存储适配器。保存使用数据库事务和内容版本检查；对象上传先完成，再提交对应记录。失败时保留可重试草稿。
5. 验证未登录和普通账户不能写入、看不到草稿/原图，管理员能编辑/上传，过期登录和并发保存有明确处理。确认迁移 37 张及全站功能后再发布。

目前没有云账号，SQL 尚未在实际 Supabase 项目执行。建表和 Storage/Auth 访问规则需在目标项目做真实权限验证；迁移材料生成器已在本机测试。数据库配置不是已部署的生产后台。
